# DPIP v0.2.0 — Prashar Lake

**Release date:** 2026-09-13

## Summary

v0.2.0 turns the post-v0.1 privacy evidence work into a stable, governed release. Its central improvement is evidence fidelity: DPIP can consume attributable runtime observations from independently owned evidence producers and make bounded composition-privacy judgments without converting successful component behavior, architectural intent or missing observations into a broader PASS.

## Key additions

### Attributable runtime evidence

DPIP now has a demonstrated path for consuming source-pinned A/B evidence for relationship identifiers, verifier transcripts, status behavior, Trust Task identifiers/evidence and policy discovery. Evidence is bound to the exact examined contexts and provenance class.

### Bounded privacy conclusions

The relationship-correlation examination reached SATISFIED for the exercised OpenVTC A/B runtime boundary. The conclusion means the named evidence obligations were satisfied for those observations. It does not establish deployment-wide, network-wide or implementation-family unlinkability.

### Data Rooms observability

The E1-E6 Data Rooms observability contract makes private-room privacy claims testable and prevents architectural capability from standing in for runtime evidence. Where private-tier membership, invitation/key-establishment, witnessed anchoring/freshness, migration or related runtime evidence is unavailable, the correct result remains evidence-required.

### Durable specialist ownership

Privacy-specific questions can now be handed off from RAHP into DPIP with preserved source pins, proposition text and return contracts. This keeps the assurance controller and specialist responsibilities separate while making the downstream trail understandable to external readers.

### Enumeration and purpose limitation

Issuer-side credential enumeration is treated as a composed disclosure surface. Authorization and body minimization are relevant controls but do not automatically settle holder-graph correlation, temporal metadata, free-text revocation reason, retention or legitimate-purpose questions.

## Evidence discipline

v0.2.0 preserves the rule that specification evidence, synthetic fixtures and runtime observations prove different things. Missing deployment evidence remains an explicit information gap. DPIP never infers privacy PASS merely because a workflow succeeded or a cryptographic primitive is privacy-capable.

## Coordinated release

This release is coordinated with RAHP v2.3.0 and Trust Protocol Interop Lab v0.6.0. The versions are intentionally independent. The Lab can produce bounded execution evidence; DPIP evaluates privacy propositions over admissible evidence; RAHP owns the broader assurance lifecycle and residual reconciliation.

## Upgrade notes

Existing v0.1 integrations using the portable result/return model can continue to interoperate. Consumers should update documentation references to v0.2.0 and use the new runtime evidence/observability surfaces only where the required provenance and evidence class are available.

## Known residuals

The release does not close private-room runtime gaps, deployment-wide observer unlinkability, issuer enumeration purpose/retention questions, or upstream semantic gaps that DPIP does not own. These remain explicit future examination or evidence triggers.
