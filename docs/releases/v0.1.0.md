# DPIP v0.1.0 — Khajjiar Lake

DPIP v0.1.0 is the first governed release of the DTG Privacy-Preserving Implementation Profile and its executable privacy-assurance specialist.

## Release proposition

DPIP evaluates privacy at the composed-interaction boundary. Component validity, selective disclosure or proof success does not by itself establish composed privacy. Conclusions are scoped to the exact proposition, source pins, evidence class and observations admitted by the examination.

## Included capability

- C1-C6 canonical interactions and RF-001-RF-004 composed flows;
- scoped privacy claims and declared/observable/effective correlation scope;
- machine-readable profiles, evidence bindings, observations, findings, results and change-impact metadata;
- deterministic evidence planning/acquisition and supplied-evidence execution;
- explicit source-backed, synthetic/calibration and runtime-upstream-observation evidence classes;
- positive, negative and adversarial executable privacy checks;
- portable `rahp-assessor-result/v1` specialist results;
- finite PASS / FAIL / INDETERMINATE / NOT_APPLICABLE return semantics;
- deterministic `evidence-required` remediation contracts;
- deterministic `model-gap` handling for unmapped evidence surfaces;
- human-readable dispositions equivalent to the formal result;
- durable specialist-return outbox markers, acknowledgement, automatic retry and idempotent reconciliation;
- shared producer/consumer contract fixtures with RAHP;
- governed release readiness and persisted Indian-lake codename identity.

## Historical blocker reconciliation

The original v0.1 readiness record treated RF-001-F001 — privacy-compatible Trust Task binding semantics — as blocking because DPIP could not yet turn the surface into a deterministic executable/evidence contract.

That blocker is resolved at the **DPIP release-capability boundary**, not by claiming that every Trust Tasks deployment is private. Current DPIP explicitly represents envelope/thread correlation surfaces, can calibrate prohibited cross-context reuse, preserves source evidence separately from runtime observations, and returns `INDETERMINATE / evidence-required` when authoritative implementation evidence is absent.

RF-001-F002 remains a non-blocking evidence limitation: candidate construction evidence cannot be silently promoted beyond its supported scope.
