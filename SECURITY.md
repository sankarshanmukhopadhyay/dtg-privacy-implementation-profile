# Security Policy

## Supported versions

Security and privacy-assurance corrections are applied to the current `main` branch and the latest governed release line identified by repository readiness/release evidence. Older versions should be treated as unsupported unless a maintainer explicitly states otherwise.

## Reporting a vulnerability

Do not open a public issue for an undisclosed vulnerability or privacy weakness that could expose deployment-sensitive information. Use GitHub private vulnerability reporting when available, or contact the repository maintainer through a private channel identified on the maintainer profile.

Include the affected revision/version, reproduction steps, privacy/security impact, affected evidence/result artifacts, and any known mitigation.

## Assurance implications

DPIP evaluates composed privacy properties; it is not a certification authority. A defect may invalidate prior privacy evidence or outcomes. Missing, stale, or inadmissible evidence must never be converted to PASS during remediation. Components and deployment/governance authorities retain the semantics and decisions that DPIP explicitly does not own.
